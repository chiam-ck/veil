Developer guide

Use the Veil CLI or REST API from your trusted team network. OCR, document editing and storage stay on this server. The configured LLM inspects extracted text; OCR and document editing stay on this server.

Download the full developer guide · API schema

Documents belong to an anonymous private browser workspace. Links work only with the owning browser cookie; tabs in the same profile share access. Clearing cookies or ending the workspace loses access. An MCP server is not implemented.

Private browser workspaces

Every preview, download, report, source reveal, ZIP, correction and deletion checks browser-workspace ownership on the server. Another browser cannot access a document using its link alone. Use separate browser profiles on shared computers. End workspace revokes access; clearing cookies or expiration has no account recovery. Server administrators and the configured model provider remain separate trust boundaries.

API clients initialize GET /api/workspace, retain the response cookie, and send X-Veil-Request: 1 on mutations. Cross-site requests are rejected. The CLI stores its own private cookie jar per server; it cannot use browser-owned job links. See the downloadable guide for API and certificate setup.

CLI quick start

cd /path/to/veil
source .venv/bin/activate
export VEIL_SERVER=https://veil.example.internal:8787
export VEIL_CA_BUNDLE=/path/to/veil-workspace-ca.crt
veil redact ./report.pdf --output ./sanitised
veil redact ./documents --recursive --output ./sanitised
veil redact ./report.docx --async --json
veil status JOB_ID --json
veil report JOB_ID --json
veil download JOB_ID --output ./downloaded
veil delete JOB_ID --json

Redaction waits and downloads by default. Outputs use opaque job folders; recursive CLI batches preserve relative parent directories. Exit codes: 0 completed, 2 review/blocked, 1 failure, 64 usage. Use --server or VEIL_SERVER for your deployment endpoint.

Browser batches

Select 1–50 documents. Each upload has its own size limit and result. Uploads retry when the shared queue is full; inference concurrency remains bounded. Download all finished outputs as a ZIP, or explicitly download a partial ZIP while other documents remain outstanding. Originals are excluded.

Bookmark the batch link to return to server-side progress. Filenames stay in the browser tab; save the filename index if you need a numbered mapping after leaving the page.

Model readiness and recovery

Before processing, Veil checks the configured model with synthetic examples and caches compatible request options. Provider outages or malformed responses put accepted jobs into Waiting for model. Jobs resume automatically with the same IDs when readiness returns; originals stay unchanged and partial output is unavailable. By default, waiting is limited to 15 minutes and three failed document attempts. Source validation and preservation checks remain mandatory.

GET /api/provider/status returns cached readiness without sending a model request. Configure readiness and retry limits in the server environment; see the full guide for details.

Correct missed PII or re-run

Open a finished document and select missed text in its preview. Choose Use selected text, then Add phrase and Apply manual redactions. You can also type a phrase. Every literal match is redacted, ignoring case; spacing must match. The document and preview are regenerated locally without a model request. Text that OCR never extracted needs source editing and another upload.

Re-run detection inspects the retained original with the current model. Earlier redactions and added phrases are kept. Both actions create a new revision in the same batch position; previous outputs stay available until their own cleanup deadline. Use Previous result and Newer result to navigate revisions. Reports and ZIPs exclude correction phrases and original text.

POST /api/jobs/JOB_ID/reprocess
Content-Type: application/json
{"mode":"manual","redactions":["SYNTHETIC MISSED TEXT"]}

# Another model pass, optionally with added phrases:
{"mode":"rerun","redactions":[]}

REST batch flow

POST /api/batches
Content-Type: application/json
{"count": 2}

POST /api/jobs
multipart: file, batch_id, batch_index=0

POST /api/jobs
multipart: file, batch_id, batch_index=1

GET /api/batches/BATCH_ID
GET /api/batches/BATCH_ID/download
GET /api/batches/BATCH_ID/download?partial=true

Batch indices are zero-based and unique. Honor HTTP 429 and Retry-After. Reconcile an interrupted submission through batch status before retrying; duplicate positions return 409 and do not overwrite files.

Dataset generation and benchmarks

veil datasets generate --suite multilingual --output ./datasets-new --json
veil benchmark ./datasets-new --output ./benchmark-new --concurrency 2 --json
pytest -q

These commands run on the machine invoking the CLI. Use fresh output directories. Historical measurements are not preservation-profile certifications.

MCP: current status

No MCP server or tools are shipped in this release. There is no veil mcp command or /mcp endpoint. Use the working REST API or CLI today.

A future MCP bridge should wrap the API: submit → POST /api/jobs, inspect → GET status/report, download → permitted sanitised artifacts. It must constrain file access and prevent original PII being returned to an external model. These are proposed mappings, not runnable MCP configuration.

Deployment

.venv/bin/python scripts/setup_workspace_tls.py --host veil.example.internal
docker compose up -d --build
docker compose ps
docker compose down

The pilot override binds your server’s private LAN interface while retaining loopback access. Configure VEIL_ALLOWED_HOSTS for your hostname. The LLM worker uses the bridge network to reach the configured provider. Configure the key, model and endpoint in the server’s private .env; browser users never supply provider credentials. HTTPS is required for network access. Trust the deployment’s public CA certificate on client devices. Workspaces expire after 24 hours of inactivity or 7 days maximum; file cleanup is separate. Older ownerless jobs cannot be claimed by opening their links.
